# MaidanMind: AI Crowd Intelligence for Indian Stadiums

> 🚀 **Live Demo Submission:** [Click here to test MaidanMind on Google Cloud]({YOUR_CLOUD_URL_HERE})

MaidanMind is an intelligent, sport-aware crowd management platform designed to eliminate the chaos, long queues, and safety risks associated with attending massive physical events in India. 

---

## 🎯 Chosen Vertical
**Sports & Entertainment Events / Smart Crowd Management**
We chose this vertical because major Indian sporting events (like the IPL, ICC matches) suffer from archaic, non-digitized crowd sorting. Fans miss almost 20% of a live game just standing in physical queues for food or restrooms, and heat-wave safety is historically poorly managed.

---

## 🧠 Approach and Logic
Instead of relying on standard raw attendance numbers, MaidanMind uses a **Sport-Context Engine**. 

**The Logic:** Human behavior at a cricket game is highly predictable *if* you understand the game. A queue for a restroom will naturally spike during an innings break, and food purchases surge when a team loses quick wickets or calls a strategic timeout.

**The Approach:** 
1. **Real-time Match Sync:** The application syncs with the live game state (e.g., Target: 169, Overs: 15.0, Recent Event: Six).
2. **Contextual AI Predictions:** If the match enters a tense endgame or a strategic timeout, the system instantly recalculates wait times across all gates, stalls, and restrooms based on psychological crowd behavior models.
3. **Hyper-localized Routing:** Utilizing a custom SVG mapping engine, fans are dynamically routed to underutilized facilities in surrounding sections to balance the load of the stadium seamlessly.

---

## ⚙️ How the Solution Works
The primary user interface is a mobile-first Progressive Web App intended for fans inside the stadium:

1. **Initialization:** The user opens the app and selects their stadium from our database of 23 fully mapped Indian venues.
2. **The Dashboard (Home):** The user is presented with their stadium’s real-time occupancy, heat levels, and a "Smart Tip" generated by the engine advising them on imminent crowd surges based on the live cricket match.
3. **Interactive Maps:** By exploring the Map tab, fans can filter the stadium blueprint to view "Heat Indexes" (identifying unsafe 40°C+ blocks) or "Crowd Density" to avoid physical bottlenecks.
4. **Virtual Queuing:** Instead of waiting in line, fans browse regional food stalls (e.g. *Vada Pav* in Mumbai) and click "Get Token". They receive a live digital countdown and only leave their seat when their token flashes "Ready!"
5. **AI Chatbot (Gemini Integrated):** A fully conversational, multilingual AI (powered by Google Gemini) acts as an intelligent assistant. It digests the massive real-time stadium data payload and can answer questions like *"When is the best time to leave to beat the traffic?"* in 7 different Indian languages.
6. **Safety & SOS:** An emergency protocol that, when activated, locks the screen, shows the absolute fastest exit route relative to the user's current crowdedness, and highlights the closest AED machine.

## 🤔 Assumptions Made
To develop and demonstrate this prototype during the hackathon, the following assumptions were made:
- **Simulated Real-time Data:** We assume access to live turnstile API data, PoS data from food stalls, and thermal camera APIs. For this submission, our `js/data.js` simulation engine perfectly mocks these external connections.
- **Connectivity:** We assume attendees have cellular data inside the stadium to fetch the lightweight (< 100KB) UI payloads.
- **Google Cloud Platform:** The architecture assumes hosting on Google Cloud Run for scalability, with Gemini serving the AI logic component concurrently.
- **Hardware Integration:** The heat index maps assume the deployment of cheap IoT thermal sensors in stadium blocks to generate the block temperatures.

## 🚀 Local Setup & Deployment

**To Run Locally (Full Experience):**
1. Clone this repository to your local machine.
2. Navigate to `js/config.js` and input your own API keys to enable the live integrations:
   - **Gemini API Key:** Replace `[ENCRYPTION_KEY]` with your Google AI Studio key to activate the intelligent Chatbot.
   - **Google Maps API Key:** Replace `'YOUR_GOOGLE_MAPS_API_KEY'` to enable future maps integrations (currently the heatmap uses native SVG fallback).
   *(Note: If you do not provide a Gemini key, the application will automatically fall back to an offline simulated data engine!)*
3. Serve the directory via any local HTTP Server (e.g., `python -m http.server 3000` or VS Code Live Server).
4. Do NOT use `file:///` protocols to open `index.html` as they block API fetch requests due to CORS policies.

**Google Cloud Build Deployment:**
This repository contains a `Dockerfile` utilizing Nginx and is ready to be directly deployed to Google Cloud Run. 
Run: `gcloud run deploy [SERVICE_NAME] --source . --region [REGION]`
